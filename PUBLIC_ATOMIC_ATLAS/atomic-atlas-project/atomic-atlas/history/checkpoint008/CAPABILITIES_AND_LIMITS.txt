ATOMIC ATLAS — CURRENT CANDIDATE CAPABILITIES

Authoritative engine: core/src/atomic_atlas_core, package version 0.0.5.dev1. Contract revision 0.2 describes existing /0.1 wire markers; these are different version axes, not competing cores.

Implemented: declarative graph construction, explicit ordered state patches, candidate overlays, source-bound observations, independent possible/preferred/required profile categories (P10), content digests, save/load guards, read-only directed route tracing, arithmetic budget preview, cooperating-writer JSONL ledger, detached supported input/output boundaries, and event-free-baseline declared-event replay.

Not implemented: physical fluid/material/thermal solvers, stochastic dynamics, full dynamic replay, LLM generation or recall, scientific causality adjudication, hostile-caller isolation, atomic transactions combining atlas JSON and ledger, general Draft 2020-12 validation, complete cross-domain conformance or stable public API guarantees. A relation or label is not a measured mechanism; replay is not experimental evidence.

Schemas are standard JSON Schema documents, but the bundled offline evaluator supports only their used keyword subset. All 12 schemas passed jsonschema 4.26.0 Draft 2020-12 metaschema/reference checks, and 5,097 bounded finite-JSON classifications agreed with the bundled evaluator. This is independent validation of these schemas and cases, not certification of every behavior. Cross-object identity, endpoints, uniqueness and sequence require model integrity checks. Evidence verified=true is a caller declaration, not independent verification by this package.

Examples A/B/C are independent standalone demonstrations. They do not import the Python core, and passing their tests does not prove core integration or universal domain substitution. A: SVG actuator abstraction and generated reference image. B: synthetic retrieval selection, optional SQLite reported-event storage; no measured LLM advantage. C: dimensionless compartment accounting and its own deterministic model receipts/replay. C's model replay is broader than the core's declared-event replay; it is still not full external physical replay.

Release work remaining: wider adversarial coverage and Windows verification, real browser checks, external review and final licensing/asset metadata for examples. The core retains its supplied MIT license. No blanket license is asserted for separately supplied examples/assets. This candidate is not published or independently approved. Final public README remains deferred.

Candidate 005: 91 full pytest cases pass, including 36 new adversarial/boundary cases; an installed wheel passed isolated Linux schema/build/event/replay/save/load checks. File readers reject duplicate JSON keys and nonfinite constants; ledger envelopes have exact fields, and canonical hashes require finite JSON values. Valid existing finite payload hashes retain their byte contract. Invalid older files require explicit inspection; no silent migration or history rewrite is performed.

Limits observed: schema-valid snapshot hashes still need comparison to trusted anchors; there is no standalone snapshot import/verifier API. Final document state is supplied, not authenticated by event replay without a baseline. JSON Schema mathematical integers such as 1.0 can pass structural validation while Event construction requires a Python int; that is a separate model policy, not a schema-validator disagreement.

PROJECT 006: Includes a source-only explicit-review proposal harness using the core Event/state model and JSONL ledger. It registers source bytes, appends proposals and decisions, requires proposal/state hash review, records linked supersession/revision, blocks unresolved uncertainty, and reconstructs accepted state from decisions. No automatic language extraction or truth adjudication is implemented. Proposal guard contract is separate from the 12 core JSON schemas. Acceptance is ACCEPTED_DECLARATION, not independent factual verification. Completed review decisions are logged; blocked attempts are not automatically logged. A retained external ledger head is needed to detect complete rehashed history replacement.

PROJECT 007: Step-7 boundary suites cover the five prohibited automatic promotions. Budget preview requires nonempty typed ledgers and uses exact rational balance comparison independent of ambient Decimal precision. Core schemas and harness implementation are unchanged. Opaque caller assertions can still be preserved as declarations; no semantic entailment/causality/physics checker is implied. Current test counts are recorded in RUN_RECEIPT.json, with specific limits in STEP7_REVIEW.txt.

PROJECT 008: Domain substitution passed 65 checks across eight distinct synthetic graph structures, using unchanged core/harness implementations, schemas and wheel. This supports the tested representation/event/review/replay workflow portability, not automatic extraction, domain-specific simulation or universal conformance. Claims and structural graphs remain separate; the harness does not automatically synchronize them. See STEP8_REVIEW.txt for coverage and next release work.
