ADVERSARIAL FINDINGS AND FIXES
AV005-01: Duplicate JSON keys were silently collapsed by the standard loader. A hidden earlier version or ledger record could disappear before validation. Strict file decoding now rejects duplicate keys at any object depth, malformed JSON and nonfinite constants. Original duplicate-document and duplicate-ledger reproductions accepted in 004, rejected in 005.
AV005-02: Ledger verification ignored unexpected fields and treated an absent record as null. Such envelope changes could retain a valid digest. Envelopes now require exactly sequence, previous_head, record and head. Added/missing-field reproductions accepted in 004, rejected in 005. This does not authenticate external authors or prevent a complete chain rewrite unless the reader retains an independent expected head.
AV005-03: Ledger append/hash serialization admitted NaN and infinities, which are outside finite JSON. Canonical hashing now checks finite JSON values; persisted output prohibits nonfinite constants. Three reproductions accepted in 004, rejected before append in 005. Rejection leaves bytes, head and count intact.

Valid finite canonical bytes/hashes preserve the prior contract; existing valid envelopes remain readable. There is no silent migration of ambiguous/invalid old files. They require explicit source inspection. Changes affect persisted input acceptance and canonical hashing; ordinary supported finite data is unchanged.

LIMITS / OPEN ITEMS
Standalone snapshot digest verification is not implemented. A formatted digest can pass a schema while being false; compare with independent trusted anchors and the actual topology/source.
Final document state is supplied, not recomputed or authenticated from events without an event-free baseline. Explicit replay can check it when that baseline is available.
Event construction requires a Python int, while JSON Schema integer accepts finite whole-number floats such as 1.0. This is a stricter model policy, distinct from structural validator agreement; no silent coercion added.
Wider adversarial/property coverage, Windows, additional Python versions, real browsers, external review and example/asset licensing remain open. Resource exhaustion/hostile direct object mutation and power-failure transactions are outside current guarantees. Examples A/B/C still are standalone, not integrated with the Python core.
