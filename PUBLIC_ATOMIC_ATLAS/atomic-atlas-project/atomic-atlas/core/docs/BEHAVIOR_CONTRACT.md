# Neutral core behavior — project 007 / core 0.0.5.dev1

Graph construction, declared state patches, candidate overlays, observations, content hashes and declared-event replay retain the original neutral APIs. This checkpoint hardens seven reproduced findings from Audit 002.

- A supplied save guard is checked against current digests before touching the destination. A blocked guard attached during load remains enforced by subsequent save. An explicit reset accepts a new lineage; callers must establish new expected hashes when adopting it.
- State inputs, stored event payloads, returned events, exported/imported state and snapshots are detached deep copies. Direct writes to the public Atlas dictionaries remain possible; this is an API contract, not a sandbox against callers modifying internals.
- Runtime events, observations and overlays are staged on a copy. They are published to the original Atlas object only after the configured ledger append returns successfully. This is not an atomic transaction combining a separately saved JSON file and ledger.
- Directed relations permit forward tracing only, unless reversible is explicitly true. Undirected relations permit either direction. Candidate relations are excluded from established route tracing. A cut removes both traversal directions of its endpoint pair. Tracing never establishes physical transport.
- Candidate entity IDs must be unique within an overlay and cannot shadow established IDs. Relation and route references may target established entities or entities within that same overlay. Cross-overlay references are rejected; candidate region references must name established regions. Candidate records remain unvalidated and cannot enable transport/state mutation.
- JSONL append acquires an exclusive sibling lock file, verifies current history and rejects a stale head/count before writing. Cooperating processes fail immediately when busy. Successful append flushes and fsyncs the file. Ordinary failed write/flush paths attempt truncation rollback. A crash can leave a lock; no automatic stale-lock deletion is performed. Inspect history before explicit recovery. Uncooperative writers, power loss, directory-entry durability and rollback failures are outside the tested guarantee.
- Declared-event replay requires an event-free, integrity-checked baseline and contiguous supplied events. Continuation replay is not implemented. It reproduces declared patches; no full dynamic physical replay or language-model recall is claimed.

Twelve current schemas are enforced at supported build/load, model insertion, profile, topology, snapshot and manifest boundaries. They passed independent Draft 2020-12 metaschema/reference and bounded differential checks; the runtime evaluator remains a used-keyword subset. Schema acceptance establishes structure, not scientific truth. See SCHEMA_CONTRACT.txt and the root validation review.

Step 7 adds adversarial coverage of connection/flow, correlation/causation, label/mechanism, candidate/validated, and replay/evidence boundaries. Budget preview requires a nonempty complete ledger with textual unit/bucket labels. Exact rational comparison of parsed finite Decimal values prevents ambient Decimal rounding from concealing imbalance. Budget preview remains arithmetic hypothesis accounting with no state mutation or physical mechanism/evidence verification.

Opaque state, attributes, source text and proposal values may contain unsupported assertions. Preserving such data is not a causal/physical inference. The core is not a semantic truth checker or hostile-caller sandbox. Step-7 tests defend the named typed/API boundaries, not all prose a caller might supply.
